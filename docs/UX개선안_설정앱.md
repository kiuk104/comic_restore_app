# 만화 한글 복원 앱 — 설정 창 UX 개선안

대상: `comic_restore_app.py`의 Tkinter 메인 창 (v0.14 기준, 760×1030)
작성일: 2026-07-13

---

## 1. 현재 상태 진단

현재 창은 위에서 아래로 약 30개의 컨트롤이 한 줄짜리 평면 폼으로 쌓여 있는 구조입니다. 구분은 가느다란 Separator 3개뿐이고 섹션 제목이 없어서, 처음 보는 사람은 물론이고 만든 본인도 "그 옵션이 어디 있더라"를 스크롤로 찾게 됩니다.

| 영역 | 컨트롤 수 | 성격 |
|---|---|---|
| 작품 프리셋 | 콤보 1 + 버튼 2 | 매 작품 1회 |
| 폴더 (원본/출력) | 경로 2 | 매 작업 |
| 업스케일 (exe·models·모델·배율·건너뛰기) | 5 | 최초 1회 + 가끔 |
| 처리 옵션 체크박스 | 7개 연속 | 대부분 기본값 유지 |
| 글자 굵기 보강 | 스핀박스 1 | 가끔 |
| 폰트 (본문·손글씨·캡션·외침·효과음) | 10줄 + 체크 2 | 작품당 1회 → 프리셋에 저장됨 |
| API·번역 (키·엔진·언어·방식·용어집·모델) | 8 | 최초 1회 + 번역 작업 시 |
| 실행 범위 (테스트 장수·페이지 범위) | 2 | 매 작업 |
| 하단 버튼 | 버튼 6 + 입력 1 | 매 작업 |

여기서 UX 관점의 핵심 문제는 버튼 개수 자체가 아니라 **"매일 쓰는 것"과 "한 번 설정하고 잊는 것"이 같은 화면, 같은 시각적 무게로 섞여 있다**는 점입니다.

구체적으로 짚으면:

**① 사용 빈도와 화면 배치가 어긋남.** 실제 반복 워크플로는 `원본 폴더 지정 → 전체 시작 → 검수 페이지 → (검수 반영 반복) → 최종본 ZIP` 다섯 걸음인데, 이 다섯 개가 화면 맨 위(폴더)와 맨 아래(버튼)로 갈라져 있고 그 사이에 "한 번 설정하면 안 건드리는" 항목 25개가 끼어 있습니다. upscayl 경로는 자동 감지까지 되는데 항상 두 줄을 차지합니다.

**② 하단 버튼 7개가 위계 없이 한 줄.** `샘플 미리보기 · 샘플번호 · 전체 시작 · 검수 페이지 · 검수 반영 · 최종본 ZIP · 중지`가 전부 같은 크기·같은 스타일입니다. 주 작업 버튼(전체 시작)과 위험 버튼(중지), 후반 단계 버튼(ZIP)이 구분되지 않고, "중지"는 실행 중이 아닐 때도 항상 눌리는 모양으로 존재합니다. 3D 툴로 비유하면 렌더 버튼과 렌더 취소 버튼이 나란히 상시 활성화된 상태입니다.

**③ 설명문이 컨트롤 라벨 안에 들어가 있음.** "Batch API 전사 (50% 할인 — 완료까지 대기, 샘플엔 미적용)"처럼 괄호 설명이 라벨에 붙어 체크박스 7개가 시각적으로 문장 덩어리 7줄이 됐습니다. 훑어볼 때 키워드가 안 잡히고, 창 폭도 이 설명들이 결정하고 있습니다.

**④ 옵션 간 의존 관계가 표현 안 됨.** `전사·재조판 건너뛰기`를 켜면 Batch API·Claude 모델·API 키가 의미 없어지고, `번역 방식`은 원서 언어가 한국어면 무관하며, 손글씨 폰트는 `손글씨 재조판`이 꺼져 있으면 쓰이지 않습니다. 지금은 전부 항상 활성 상태라 "이걸 켜면 저건 어떻게 되지?"를 사용자가 머리로 추적해야 합니다.

**⑤ 실행 상태 피드백이 로그뿐.** 진행률 표시가 없고, 실행 중에도 설정을 바꿀 수 있어 보입니다(실제 반영 안 되는데 되는 것처럼 보임 — 거짓 어포던스).

**⑥ 창 높이 1030px 고정.** 노트북(768~900px 높이)에서는 하단 버튼이 잘립니다.

## 2. 개선 원칙

제안의 뼈대는 세 가지입니다.

1. **빈도 기반 분리** — 매 작업 쓰는 것만 첫 화면에, 나머지는 탭/접기로.
2. **워크플로 순서의 시각화** — 실행 → 검수 → 내보내기가 버튼 배치에서 읽히게.
3. **상태의 정직한 표현** — 지금 할 수 있는 것만 활성화, 진행 중이면 진행 중으로 보이게.

## 3. 제안 A — 탭 구조 재편 (권장, 핵심안)

`ttk.Notebook`으로 4개 탭 + 항상 보이는 하단 고정 영역으로 나눕니다.

```
┌────────────────────────────────────────────────┐
│ 작품 프리셋 [카이지        ▼] [저장] [삭제]      │  ← 항상 표시 (탭 위)
├─[ 실행 ]─[ 보정 옵션 ]─[ 폰트 ]─[ 환경 설정 ]───┤
│                                                │
│  ── 실행 탭 ──                                  │
│  원본 폴더  [D:\i\comics\...      ] [찾아보기]   │
│  출력 폴더  [비우면 자동           ] [찾아보기]   │
│  페이지 범위 [    ]  테스트 장수 [ 0 ]           │
│  샘플 번호  [ 3 ]                               │
│                                                │
│  ▸ 이번 실행 요약: 업스케일 2x · 합의 전사 ·     │
│    본문 나눔명조 · 손글씨 보존 · 번역 없음        │  ← 다른 탭 설정 요약
│                                                │
├────────────────────────────────────────────────┤
│ [▶ 전체 시작]  [샘플 미리보기]   │ 1단계: 처리   │
│ [검수 페이지]  [검수 반영]       │ 2단계: 검수   │
│ [최종본 ZIP]                    │ 3단계: 완성   │
│ ████████████░░░░░  14/30 페이지  [■ 중지]       │
│ ┌ 로그 ────────────────────────────────────┐   │
│ └───────────────────────────────────────────┘  │
└────────────────────────────────────────────────┘
```

각 탭의 내용:

**실행 탭** — 폴더 2개, 페이지 범위, 테스트 장수, 샘플 번호. 그리고 "이번 실행 요약" 한 줄: 다른 탭에서 정한 설정을 읽기 전용 텍스트로 요약해 줍니다. 탭으로 숨기면 "지금 어떤 설정으로 도는지" 불안해지는 단점이 있는데, 요약 줄이 그걸 상쇄합니다.

**보정 옵션 탭** — 체크박스 7개 + 글자 굵기 보강 + 업스케일 모델/배율. 여기서 체크박스를 성격별로 `LabelFrame` 3묶음으로 나눕니다: "실행 방식"(이어하기, Batch API, 전사·재조판 건너뛰기), "화질·배경"(원본 보존, 말풍선 채움, 흰 채움, 굵기 보강), "업스케일"(모델, 배율, 건너뛰기).

**폰트 탭** — 아래 제안 C의 그리드로 압축.

**환경 설정 탭** — upscayl 경로 2개, API 키, 크레딧 링크, 전사 엔진, Claude 모델, 번역 4종(원서 언어·방식·합의·용어집). 최초 1회 성격의 것들. 번역은 쓰는 작품이 정해져 있으니 "번역" `LabelFrame`으로 묶고, 원서 언어가 한국어면 나머지 번역 컨트롤을 `state="disabled"` 처리합니다.

**하단 고정 영역**(탭 밖) — 버튼 + 진행바 + 로그. 어느 탭에 있든 실행/검수/로그는 항상 보입니다.

이 구조의 효과: 창 높이가 1030 → 약 650~700px로 줄어 노트북에서도 잘리지 않고, 매일 쓰는 화면(실행 탭)에는 컨트롤이 6개만 남습니다.

## 4. 제안 B — 하단 버튼의 워크플로 그룹화 + 위계

탭을 안 하더라도 이것만은 권장합니다. 현재 한 줄 7개를 **단계별 3그룹**으로 나누고 시각적 무게를 다르게 줍니다.

```
  ① 처리                ② 검수               ③ 완성
 ┌───────────────────┐ ┌─────────────────┐ ┌──────────┐
 │ [▶ 전체 시작]      │ │ [검수 페이지]     │ │ [최종본   │
 │ [샘플] 번호[3]     │ │ [검수 반영]       │ │   ZIP]   │
 └───────────────────┘ └─────────────────┘ └──────────┘
 ████████████░░░░░░░░  14/30  경과 12:40        [■ 중지]
```

구현 포인트:

- **Primary 버튼 강조**: `ttk.Style`로 `Accent.TButton`(굵은 글씨 + 큰 패딩)을 만들어 `전체 시작`에만 적용. ttk 기본 테마에서도 `style.configure("Accent.TButton", font=("맑은 고딕", 10, "bold"), padding=(14, 6))` 정도면 충분히 구분됩니다.
- **중지 버튼은 실행 중에만**: 평소 `state="disabled"`(또는 숨김), `state["running"]=True`일 때만 활성화. 반대로 실행 중에는 `전체 시작`·`검수 반영`·`최종본 ZIP`을 비활성화. 이미 `state` dict와 `poll()` 루프가 있으니 poll에서 버튼 상태를 갱신하면 됩니다.
- **샘플 번호 입력을 샘플 버튼 옆에 붙이기**: 지금은 `샘플 미리보기` 버튼과 `전체 시작` 사이에 끼어 있어 "전체 시작의 옵션"처럼 오독됩니다. `샘플 미리보기 [3]`처럼 한 덩어리로.
- **진행바**: `ttk.Progressbar` + "n/전체 페이지" 라벨. `run_job`이 페이지 단위 로그를 이미 내니, 로그 큐에 `("progress", i, total)` 튜플을 함께 넣어 poll에서 갱신하는 방식이면 파이프라인 수정 없이 가능합니다. Batch 대기처럼 페이지 카운트가 없는 구간은 indeterminate 모드로 돌리면 됩니다.

## 5. 제안 C — 폰트 5종을 그리드 하나로

현재 폰트 영역은 10~12줄(본문·손글씨·캡션·외침·효과음 × 프리셋+경로)로 가장 큰 면적을 차지합니다. 구조가 전부 동일하므로 표 하나로 접을 수 있습니다.

```
 용도      재조판   프리셋                경로(직접 지정 시)
 본문       (항상)  [나눔명조 Bold  ▼]   [............] [...]
 손글씨     [ ]     [자동 감지      ▼]   [............] [...]
 캡션       (항상)  [본문과 동일    ▼]   [............] [...]
 외침       (항상)  [본문과 동일    ▼]   [............] [...]
 효과음     [ ]     [자동 감지      ▼]   [............] [...]
```

경로 열은 프리셋이 "직접 지정"일 때만 활성화하면 평소엔 5줄짜리 깔끔한 표가 됩니다. `on_*_preset` 핸들러 5개도 kind 리스트를 도는 루프 하나로 합쳐져 코드도 짧아집니다(현재 거의 복붙 5벌). "손글씨 대사도 재조판"·"효과음도 재조판" 체크박스는 해당 행의 "재조판" 열로 들어가 의미가 자리로 표현됩니다.

## 6. 제안 D — 설명문을 툴팁/헬프로 이동

체크박스 라벨은 키워드만 남기고, 긴 설명은 마우스 오버 툴팁으로 옮깁니다.

| 현재 라벨 | 제안 라벨 | 툴팁 |
|---|---|---|
| Batch API 전사 (50% 할인 — 완료까지 대기, 샘플엔 미적용) | Batch API 전사 (50% 할인) | 완료까지 대기함 · 샘플엔 미적용 |
| 원본 글자 영역 흰 채움 (색 배경 위 잔영까지 제거 — 테두리·그림 선은 보호) | 글자 영역 흰 채움 | 색 배경 위 잔영까지 제거, 테두리·그림 선은 보호 |
| 완료된 페이지 건너뛰기 (이어하기 — 크레딧 절약) | 이어하기 | _final.png 있는 페이지 건너뜀 — 크레딧 절약. ink_boost 변경 시엔 꺼야 재처리됨 |

툴팁은 표준 라이브러리 `idlelib.tooltip.Hovertip`을 그대로 쓸 수 있습니다(`Hovertip(widget, "설명", hover_delay=400)`). 외부 의존성 0. 페이지 범위의 긴 예시문("예: 5-20 · 5-…")과 번역 각주(※ 줄)도 같은 방식으로 옮기면 창 폭을 결정하던 문장들이 사라집니다. 참고로 이어하기 툴팁에 "ink_boost 변경 시 꺼야 함"을 넣은 것처럼, 툴팁은 지금 README에만 있는 함정 정보를 제자리에 두는 통로도 됩니다.

## 7. 제안 E — 의존 관계의 활성/비활성 연동

체크·선택 값에 따라 무의미해지는 컨트롤을 회색 처리합니다. `trace_add("write", ...)`로 변수 감시 → 관련 위젯 `state` 토글.

- `전사·재조판 건너뛰기` ON → Batch API·Claude 모델·전사 엔진·API 키 비활성 (감지만 하므로)
- `전사 엔진`이 로컬(윈도우/tesseract/easyocr) → Batch API 비활성, API 키는 번역 모드가 아닐 때 비활성
- `손글씨 대사도 재조판` OFF → 손글씨 폰트 행 비활성
- `효과음도 재조판` OFF → 효과음 폰트 행 비활성
- `원서 언어` = 한국어 → 번역 방식·합의·용어집 비활성
- `업스케일 건너뛰기` ON → 모델·exe·models 폴더 비활성

이건 문서 없이도 "아, 이 옵션은 저것과 연결돼 있구나"를 화면이 알려주는 가장 싼 방법입니다.

## 8. 우선순위와 예상 작업량

| 순위 | 항목 | 효과 | 작업량 |
|---|---|---|---|
| 1 | B. 버튼 그룹화·위계·중지 토글 | 매일 체감, 오조작 방지 | 소 (~1시간) |
| 2 | D. 툴팁으로 설명 이동 | 창 폭·훑기 개선 | 소 (~1시간) |
| 3 | A. 탭 구조 재편 | 근본 해결, 창 높이 해결 | 중 (반나절) — 위젯 이동 위주, 로직 변경 없음 |
| 4 | C. 폰트 그리드 | 최대 면적 압축 + 코드 중복 제거 | 중 |
| 5 | E. 활성/비활성 연동 | 학습 비용 감소 | 중 (관계 정의가 관건) |
| 6 | 진행바 | 실행 피드백 | 소~중 (run_job에 콜백 추가) |

1·2번만 먼저 해도 "산만함"의 절반은 해소됩니다. A는 `v` dict와 `collect_cfg()`가 이미 위젯 배치와 분리돼 있어서, 위젯의 부모 프레임만 바꾸면 되는 안전한 리팩터링입니다 — 설정 저장·프리셋·파이프라인 코드는 한 줄도 안 건드립니다.

## 9. 하지 않기를 권하는 것

마법사(단계별 위저드) 방식은 권하지 않습니다. 이 앱은 같은 설정으로 반복 실행하는 도구라서, 매번 다음-다음-다음을 누르게 하는 위저드는 오히려 느려집니다. 또한 설정을 별도 창(모달 다이얼로그)으로 빼는 것도 비추천 — 작품 프리셋 저장/복원이 현재 `v` dict 스냅샷 방식이라 창이 갈라지면 프리셋 로직이 복잡해집니다. 탭이 현재 코드 구조와 가장 궁합이 좋습니다.
